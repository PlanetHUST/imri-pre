# IMRI Script Reorganization — Compact Implementation Specification

## Goal

Reorganize execution and diagnostics **without changing current physics**.

Target behavior:

```text
scripts/main.py
  = run the full local IMRI simulation
  + save canonical outputs
  + generate plots describing that run

diagnostic scripts
  = test one subsystem with controlled inputs
  + generate focused validation plots
  + never run the full workflow unless explicitly testing integration

src/
  = sole owner of scientific implementation
```

Before editing, inspect the live source and current docs. When this file conflicts with current authoritative specifications, follow the repository authority order in `docs/README.md`.

---

## 1. Hard constraints

Do not change, retune, or reimplement physics while doing this task.

Preserve:

- pAGN disk model and physical `Q=1` outer boundary;
- damping equations and embedding criteria;
- KII/Crida gap selection;
- Type-I / thermal / Type-II migration prescriptions;
- gas/GW routing and trap semantics;
- intrinsic IMRI definition in the event-rate layer;
- current LISA PSD, waveform approximation, SNR integration, and threshold semantics;
- canonical CSV/JSON schemas unless a compatibility-preserving extension is required;
- distinction between intrinsic candidate, physical LISA entry, and LISA detectability.

Do not add merger-tree weighting, cosmological volumetric rates, or new channels.

Architecture rule:

```text
scripts/CLI -> workflows -> physical modules -> typed results
                                  |
                                  v
                         persistence -> plots
```

Plots and tests must call production functions. Never copy a production equation into a diagnostic as an alternative implementation.

---

## 2. `scripts/main.py`: one normal production entry point

`main.py` becomes the standard end-to-end command.

Required sequence:

```text
CLI/config
-> IMRIDynConfig
-> run_simulation(...)
-> canonical persistence
-> simulation-level plots
-> concise terminal summary
```

Keep `main.py` thin. It coordinates APIs; it does not own formulas.

A normal command:

```bash
python scripts/main.py
```

must produce both scientific data and figures for the same run.

Recommended CLI controls to preserve/expose:

```text
--seed
--output-dir
--disk-model
--redshift
--duty-cycle-myr
--n-repeats
--smbh-mass-grid
--nsc-mass-grid
--lisa-min-gw-frequency-hz
--lisa-max-gw-frequency-hz
--lisa-mission-duration-years
--lisa-snr-threshold
--plots / --no-plots
```

Plots should be enabled by default for normal use.

## 3. Deterministic seeding

Use a fixed default base seed for `main.py`:

```python
DEFAULT_BASE_SEED = 20260913
```

The user may override it with `--seed`.

Do **not** replace existing task-level reproducibility with one global mutable RNG. Preserve the current stable task identity, conceptually:

```text
SeedSequence(base_seed, smbh_index, nsc_index, repeat_index)
```

Keep redshift and migration scenario excluded where required for paired comparisons.

Persist enough seed identity to reproduce a repeat.

Mandatory regression:

```text
same config + same seed -> same scientific outputs
```

Also prove:

```text
plots enabled vs disabled -> identical scientific outputs
```

Plot selection/mock generation must use an independent deterministic RNG or deterministic sorting and must never advance the production RNG.

## 4. Production figures generated by `main.py`

Generate figures **after** successful persistence. Plotting must not rerun physics.

Recommended output layout:

```text
<run>/
├── imri_events.csv
├── imri_repeat_results.csv
├── imri_averaged_results.csv
├── simulation_metadata.json
├── intermediate/
└── figures/
    ├── disk/
    ├── population/
    ├── migration/
    ├── entry/
    ├── lisa/
    └── rates/
```

Use existing plotting modules/helpers where possible.

### 4.1 Disk

Generate compact disk diagnostics from the production disk model, including:

```text
Sigma(R)
H/R
Q(R), with Q=1 and R_Q=1 marked
```

### 4.2 Population / outcome flow

Visualize major counts without inventing a false funnel.

Keep explicit names such as:

```text
sampled
disk crossing
embedded
gw propagation eligible
physical LISA entry
LISA detectable
```

Only connect stages as a strict funnel when the current counters are genuinely nested.

### 4.3 Migration / transport

From persisted event and migration diagnostics, visualize at least:

```text
initial -> gas-final radius
transport status
trap-bound cases
entry reached by gas
gas-to-GW handoff
duty-cycle limited
migration error/unavailable
```

### 4.4 LISA entry

Show physical entry/boundary behavior, including:

```text
formal entry vs ISCO
formal entry vs migration lower boundary
in-domain / handoff / inside-ISCO / profile-error status
```

Unsupported/unavailable states are never plotted as physical zero.

## 5. Real-candidate LISA visualization in the production run

`event_rate.py` remains the owner of intrinsic candidate formation. Detector code only classifies downstream candidates.

Production flow:

```text
intrinsic candidate
-> detector-frame quantities
-> mission frequency window
-> integrated LISA SNR
-> detectable / below threshold / no overlap / unavailable
```

`main.py` should generate real-candidate detector figures from persisted events.

Required figures when data exist:

```text
figures/lisa/
├── characteristic_strain_candidates.*
├── snr_vs_detection_redshift.*
├── mass_redshift_detectability.*
└── detection_status_summary.*
```

### Characteristic-strain convention

Use the existing production PSD and Fourier inspiral amplitude. For visualization define:

```text
h_n(f)     = sqrt[f S_n(f)]
h_c,eff(f) = (4/sqrt(5)) f |h_tilde(f)|
```

consistent with the implemented SNR density:

```text
d rho^2/d ln f = [h_c,eff(f)/h_n(f)]^2
```

Formal detectability remains the **integrated production SNR threshold**, not visual curve crossing.

For many events, plot a deterministic representative subset of tracks; use all events for population/scatter summaries.

Use `detection_redshift` for detector-facing plots where that is the physical detector epoch.

## 6. Diagnostic scripts: one subsystem each

Diagnostics must run cheaply and independently from the full simulation.

Preferred roles:

```text
disk_test.py
  disk profiles, Q=1 boundary, finite/positive checks

damping_test.py
  controlled orbit/node cases, a/e/i trajectories, embedding predicate

migration_test.py
  raw signed torque, gap branch, traps, migration integration

trap_test.py
  keep only if trap logic is clearer separate; otherwise merge into migration_test.py

gas_gw_handoff_test.py
  controlled routing and boundary cases

lisa_detectability_test.py
  detector physics, mock mass/redshift populations, sensitivity/SNR plots

rate_visualization_test.py
  synthetic/persisted-table plotting, status conservation, unavailable-vs-zero

output_schema_test.py
  only if schema checks are not already cleanly owned elsewhere
```

Each diagnostic should contain:

```text
explicit controlled inputs
-> production function calls
-> independent assertions/invariants
-> compact terminal result
-> numerical plot data when useful
-> focused figures
```

No full `run_simulation()` call merely to obtain test data.

## 7. LISA mock visualization belongs only in `lisa_detectability_test.py`

Mock sources are for detector understanding, not production results.

Support three compact experiments.

### A. Fixed source, varying redshift

Hold source-frame masses fixed and scan a dense redshift grid.

Persist:

```text
m1_source_msun
m2_source_msun
redshift
luminosity_distance_mpc
chirp_mass_source_msun
chirp_mass_detector_msun
f_isco_observer_hz
f_low_hz
f_high_hz
lisa_snr
snr_status
is_detectable
```

Plot:

```text
source tracks vs LISA characteristic noise
SNR vs redshift
```

### B. Mass-redshift grid

Use controlled `(M1, M2, z)` values and call only the production detector API, e.g. `evaluate_lisa_inspiral_snr(...)`.

Plot `rho(M1,M2,z)` and the configured threshold boundary where supported by the grid.

### C. SNR contribution

For representative sources plot:

```text
d rho^2 / d ln f
```

against observed frequency to show which frequencies supply the integrated SNR.

Mock outputs go under `diagnostics/lisa_detectability/`, never under a production run directory.

## 9. Plot/data rules

For scientifically important figures, save plotted numerical data beside the figure.

Example:

```text
figure.png
data/figure.csv
```

Candidate-track data should include at least:

```text
candidate_id
frequency_observer_hz
h_c_eff
h_n
in_detector_band
in_snr_window
```

Use fixed canonical physical units in saved scientific data. Display rescaling belongs only to presentation.

Keep detector states distinct:

```text
detectable
below threshold
no overlap
required input unavailable
model unavailable
numerical failure
not evaluated
```

Never convert unavailable states to physical zero.

## 10. Verification gates

Run the cheapest checks first.

### Gate 1 — source inspection

Before coding:

- inspect current scripts and source owners;
- identify every full-workflow caller;
- identify reusable plotting helpers;
- identify duplicated equations in diagnostics;
- record baseline output schemas/names.

### Gate 2 — subsystem diagnostics

Each diagnostic runs without the full workflow and passes its assertions.

### Gate 3 — deterministic reduced production run

Run a small real configuration twice with the same seed.

Require matching scientific outputs.

### Gate 4 — plotting invariance

Same reduced run with plots on/off.

Require identical event/repeat/average scientific content except allowed runtime metadata.

### Gate 5 — LISA consistency

Verify:

- detector plots consume intrinsic candidates rather than redefine them;
- plotted detector-frame masses/frequencies/redshifts match production outputs;
- characteristic-strain convention reproduces the implemented SNR-density relation;
- plotted SNR equals persisted production SNR;
- unavailable/no-overlap states remain distinct.

### Gate 6 — repository checks

Run the repository-configured equivalents of:

```bash
python -m compileall src scripts
pyright
git diff --check
```

Use the existing environment; do not create a replacement environment for this task.
